# フロントエンドレビュー

指定された差分と変更目的を確認する。判断に必要な既存の呼び出し元、共通 UI、テストも読む。共通のルールと指摘の形式は [AGENTS.md](../../AGENTS.md#セルフレビュー)、UI と API クライアントの方針は [Frontend System](../../docs/frontend-system.md) に従う。

## 実装観点

- React Router の画面遷移とアクセス制御を確認する。直接 URL を開いた場合、再読み込み、セッション確認中、未認証、権限不足で意図した表示や遷移になるかを見る。
- 変更した画面で、読み込み中、データなし、失敗、成功のうち起こり得る状態を確認する。フォームでは React Hook Form と Zod の検証、送信中の多重操作、API エラーの表示と再試行を見る。
- TanStack Query のキーと更新・無効化の対象を確認する。保護された query が `protected-query.ts` の helper でユーザーとセッションごとに分離され、サインアウトやセッション切替後に古い応答やキャッシュが表示されないかを見る。
- 入力ラベル、キーボード操作、フォーカス移動、エラーの伝わり方を確認する。画面幅を変えたときの崩れや操作不能も、変更に関係する範囲で確認する。
- 重要な UI 状態を Vitest で、画面遷移や主要操作の回帰を Playwright で確認できるかを見る。UI や API の挙動変更では、実装担当から共有された E2E の結果を確認する。

## コーディング規約

- 機能固有の表示、hook、helper は `apps/web/src/features/<feature-name>` にまとめる。通信、セッション、フォームの副作用は hook に置き、表示コンポーネントの責務を明確にする。
- 共通状態やダイアログには既存の共通 UI を使う。通常の UI は `components/ui` を優先し、複雑なウィジェットには既存の Material UI の方針を適用する。クラス結合には `cn`、通常のアイコンには `lucide-react` を使う。
- ブランド色、角丸、書体を変更した場合は Tailwind のトークンと MUI テーマの両方を確認する。
- 通常の API 呼び出しには生成クライアントと既存の Query 設定、Better Auth には専用クライアントを使う。生成環境が未整備の経路や最小限の初期化処理は AGENTS.md の例外に従う。保護 API の `credentials: 'include'` を確認し、生成型の手編集や型の二重管理がないかを見る。
- Prettier、ESLint の import/export 順、`@/*` の使い方と AGENTS.md の行数管理に従っているかを確認する。

## レビュー結果

変更したファイルは編集せず、指摘を重大度順に返す。各指摘に P0〜P3、ファイルと行、発生条件または規約の根拠、影響を添える。対象差分と関係のある指摘に絞り、任意の提案と未検証事項は分ける。要修正の指摘がなければ、その旨を返す。
